从概念到实践

行动、观察、规划及停止

观察、选择、行动、检查计划是关于下一步的假设把进展和终止作为显式状态
01 / FIELD NOTES

观察、选择、行动、检查

理解 Agent，重点看它怎样与环境交互。

任务提供目标及约束；系统观察局部信息、选择动作、获得工具结果、更新工作状态，再决定是否继续。环境可以包含文件、服务、用户或模拟世界。真实状态通常不能完全观察，发现与假设矛盾时应调整计划。

LLM 可以选择下一个动作，但运行时决定哪些动作能执行。固定工作流规定路线；Agent 根据观察选择部分路线。实用系统常将确定性阶段与其中的模型决策组合。更自主不自动意味着更可靠。

Teaching model: aₜ = policy(observation history, goal) Environment: stateₜ₊₁ → observationₜ₊₁ Runtime: validate(aₜ) before execution

02 / FIELD NOTES

计划是关于下一步的假设

用观察结果支持计划的每次延伸。

代码修复先复现或检查失败、定位行为、修改，再验证相关属性。计划可识别依赖及并行任务，但完成需要实际证据。看似合理的动作序列仍可能使用错误文件、过期数据或遗漏副作用。

多 Agent 在子任务输入清楚、输出独立且可合并时有帮助，但增加通信成本、上下文重复及修改冲突。先使用单 Agent 和确定性检查，再根据实际收益决定是否委派。

03 / FIELD NOTES

把进展和终止作为显式状态

不能正确停止的 Agent 很难稳定运行。

状态 / 事件所需行为
完成输出满足验收条件并有证据
受阻明确缺失输入或权限，保存可恢复检查点
工具超时重试前确认是否已产生副作用
反复无进展改变假设，或停止并给出有限失败报告
预算耗尽 / 取消停止新工作，返回当前状态及未完成项

循环上限限制损害和成本，不证明正确性。工具可通过幂等键区分重放和新请求；重复“继续”不应重复支付、发送消息或部署。
