01 / FIELD NOTES

Prefill, decode and the KV cache

Inference uses learned weights to compute an output for the current input.

Prefill processes the supplied prefix. Decode repeatedly computes and selects the next token. A KV cache reuses earlier attention keys and values instead of recomputing them at every step. It consumes memory that grows with sequence length and architecture details. It is not a durable project memory or a record of verified facts.

Time to first token and total completion time answer different questions. Measure your own workload, including retrieval and tools. Batching improves throughput but can change latency. Quantization reduces numerical precision and memory use; quality and speed effects depend on the hardware, kernels and task.

02 / FIELD NOTES

Sampling changes the selection rule

Temperature and top-p shape the distribution; neither verifies a claim.

Temperature rescales logits before selection. A smaller value generally concentrates mass; top-p retains a set of candidates whose cumulative mass reaches a chosen threshold. Greedy selection picks a highest-scoring candidate. None of these makes a wrong high-probability answer true. Even low randomness does not promise bit-for-bit reproducibility across every service or hardware configuration.

Supported controls differ by model and endpoint. Do not paste a sampling parameter from another model’s example without checking the current schema. For extraction, first fix the evidence and output contract; then evaluate decoding choices.

03 / FIELD NOTES

Reasoning budgets are a resource choice

Training for reasoning and spending compute during inference are separate ideas.

Some systems can allocate more inference computation before returning an answer. Other techniques generate candidates, run checks and select or repair a result. More compute can help a difficult task but costs time and may not repair missing evidence. A visible explanation or reasoning summary is not a complete execution trace or proof of internal causality.

Compare task success, p95 latency and cost per accepted result under a fixed dataset. Model names, exact budgets, available settings and pricing change; this atlas teaches the measurement method and links to current documentation rather than fixing a model leaderboard.
