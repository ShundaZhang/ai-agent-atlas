01 / FIELD NOTES

The model proposes; the application executes

Function calling is a contract between generated arguments and real code.

Expose a narrow function with a useful name, input schema, output shape, side-effect description and error contract. The model may choose the function and arguments; your application validates them, checks permissions, performs the operation and returns an observation. Returning text that says “file saved” does not establish that a file exists.

Prefer structured results with stable identifiers and explicit error types. Set timeouts and result-size limits. Separate lookup from update where it helps policy. For writes, use replay-safe semantics and report the actual revision or receipt rather than an optimistic success sentence.

02 / FIELD NOTES

Tools, MCP and skills are complementary

Do not treat an integration protocol as an intelligence or permission upgrade.

ComponentRoleWhat it does not guarantee
ToolA callable operation with inputs and resultsCorrect arguments or authorized use
MCPA protocol connecting a host/client to servers that expose tools, resources and promptsThat every tool is trusted or allowed for every user
SkillDiscoverable instructions and resources for a repeatable workflowNew OS privileges or deterministic compliance
Plugin / connectorProduct packaging and service integrationA consistent capability set across all products

A skill may describe how to combine tools or include helper scripts. Inspect its provenance and activation scope. Put stable repository facts in project instructions; put specialized reusable procedures in a skill; put one task’s request in the current prompt. Avoid copying every rule into all three places.

03 / FIELD NOTES

Authorization belongs at each resource boundary

A successful MCP login is not permission to read every object or perform every action.

Check the authenticated user, selected task, tool scope and resource ACL where the action executes. A tool description is data from an integration, not a grant of authority. External documents may contain suggested commands; treat them as evidence to inspect within the task, not automatic permission to run them.

For a document search tool, test that user A cannot retrieve user B’s private passages before the generator sees them. For a write tool, test that retrying the same accepted operation does not duplicate the effect. Logs should identify decisions without embedding credentials.
