01 / FIELD NOTES

让任务结果可以验收

有效提示是一份任务规格；遗漏的信息会影响结果。

描述目标、受众、权威输入、输出及重要约束，加入可在模型外检查的成功条件。格式或领域惯例有歧义时给出示例。先简洁，再针对真实约束或失败补充。

任务：比较提供的两份协议草案。
输出：需求变化表，附章节定位。
保留：规范性文本与评注的区别。
完成条件：每项变化能在两份草案中核对；标注歧义。

02 / FIELD NOTES

使用输出契约与独立验证器

合法 JSON 回答语法问题，不回答所有语义问题。

Schema 可约束字段、枚举和类型；应用仍需检查标识、出处、范围及业务规则，并显式处理拒绝、不完整输出和 API 错误。例如从报告抽取温度，合法数值字段仍可能包含错误单位或编造数值。

Few-shot 示例应涵盖边界行为：证据缺失、数值冲突以及允许的“未知”。要评估新案例，避免不断修改提示来记住同一小批样例。

03 / FIELD NOTES

修改提示前先定位失败层

很多看起来像提示的问题，实际来自数据、检索、工具或验证。

观察优先调查
输入资料不包含正确答案证据缺失、检索召回或范围
引用已废弃文档版本过滤、来源权威性和上下文选择
Agent 声称修改但没有 diff工具可用性、执行结果及完成条件
格式正确的对象违反访问规则应用授权，而不只是生成指令
