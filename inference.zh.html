01 / FIELD NOTES

Prefill、Decode 与 KV cache

推理使用已有权重，为当前输入计算输出。

Prefill 处理输入前缀；Decode 重复计算并选择下一个 token。KV cache 重用先前的注意力 key / value，避免每步重新计算，内存占用随序列长度及架构变化。它不是项目持久记忆，也不是已核验事实库。

首 token 延迟与总完成时间回答不同问题；测量应包含实际检索和工具。批处理可提高吞吐，也可能影响延迟。量化降低数值精度和内存占用；质量及速度效果依赖硬件、算子与任务。

02 / FIELD NOTES

采样改变的是选择规则

Temperature 和 top-p 调整分布，但都不核验主张。

Temperature 在选择前缩放 logits；较小值通常使概率集中。Top-p 保留累计概率达到阈值的一组候选；贪心选择最高分候选之一。这些方法都不会让高概率错误答案变成正确答案；较低随机性也不保证所有服务或硬件配置下逐比特复现。

模型和端点支持的参数不同，不能未经检查就复制另一模型的采样参数。抽取任务应先明确证据与输出契约，再评估解码选项。

03 / FIELD NOTES

推理预算是一项资源选择

针对推理能力训练与推理时增加计算量是两个不同概念。

某些系统可在返回答案前分配更多推理计算；其他方法生成多个候选，检查后选择或修复。增加计算量可帮助困难任务，但耗时，也不一定弥补缺失证据。可见解释或推理摘要不是完整执行追踪，也不能证明内部因果过程。

在固定数据集上比较任务成功率、p95 延迟和每个可接受结果成本。模型名称、预算、设置及价格会变化；本站介绍测量方法并链接当前文档，不固化模型排行榜。
