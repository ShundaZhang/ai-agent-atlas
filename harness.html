01 / FIELD NOTES

The runtime around the model

Harness is a broad engineering term; its exact responsibilities vary across implementations.

For this atlas, an agent harness assembles model input, exposes tool definitions, routes proposals, records observations and drives the next turn. It also connects termination, timeouts, state persistence and the application’s permission checks. A model weights file cannot perform these jobs by itself. A test harness, by contrast, drives cases and assertions; both meanings occur in engineering.

Separate control from compute. The trusted application can own identity, tool policy and durable audit state, while a sandbox handles scoped files and commands. A container is an execution environment, not the whole harness and not a complete security boundary by default.

02 / FIELD NOTES

The loop is small; the contracts are the hard part

The following is provider-neutral pseudocode, not an OpenAI API recipe.

for turn in range(max_turns):
    context = assemble(goal, trusted_rules, observations, checkpoint)
    proposal = model_step(context, allowed_tool_schemas)
    if proposal.is_final:
        return verify_final(proposal, acceptance, observations)
    call = validate_schema(proposal)
    authorize(user, task_capability, call)
    result = execute_with_timeout_and_idempotency(call)
    observations.append(normalize(result))
    persist_checkpoint(observations, workspace_revision)
return stopped("turn_budget", checkpoint)

Schema validation checks shape. Authorization checks the actor, resource and action. Execution reports success or failure. Verification checks the task property. Keep these decisions separate: a schema-valid request can be unauthorized, and an authorized successful tool call can still produce the wrong artifact.

03 / FIELD NOTES

Resume from facts, not a hopeful summary

Durable sessions need artifact and side-effect accounting.

A useful checkpoint records the task and constraints, last observed tool result, tool-call IDs, workspace revision, verified outputs, unresolved work and resource consumption. After reconnecting, inspect current artifacts and reconcile pending actions. Do not infer that an interrupted call failed merely because its response was lost.

Retry transient failures with limits and backoff; do not blindly retry a deterministic schema error. Minimize tool results before returning them to context, but retain raw evidence where it can be inspected. Trace the tool path and observed effects without collecting private model reasoning or unnecessary secrets.
