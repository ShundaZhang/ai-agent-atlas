01 / FIELD NOTES

Treat instructions and outside content differently

A retrieved passage can be useful evidence and still contain an unwanted instruction.

Prompt injection exploits a system’s handling of untrusted content that attempts to steer behavior. The risk becomes concrete when a model can retrieve private data, call tools or influence another interpreter. Consider the path from source input through generated decisions to an observable effect, rather than counting suspicious strings alone.

Keep task authority outside retrieved documents. Scope tools by user and resource; constrain destinations and arguments at the executor. Output filtering and model instructions can add defense, but do not replace access checks. An assistant saying “I ignored the instruction” is weaker evidence than a tool log showing the forbidden action was refused.

02 / FIELD NOTES

The whole system has an attack surface

Model risks and application risks overlap but need different tests.

SurfaceFailure to investigateTest / control
Data / model supply chainPoisoned examples, untrusted packages or changed checkpointsProvenance, signed artifacts where available, held-out checks
Memory / retrievalPrivate cross-user context, stale or malicious recordsTenant-aware access checks, versioning and expiration
Tools / credentialsBroad authority exposed to generated codeNarrow capabilities, external credential broker, audit
Generated outputUnsafe SQL, HTML or shell interpretationParameterization, encoding and typed interfaces
Resource useRunaway loops, huge outputs or repeated costly callsTurn/time/result limits and cancellation

03 / FIELD NOTES

Test a denied action and a valid action

A useful policy test establishes both enforcement and continued legitimate operation.

In a synthetic tenant-A task, propose reading a tenant-B record and verify denial before its contents are returned. Then read the authorized tenant-A fixture and verify success. Inject a tool timeout and check that the run reports a bounded failure. Test duplicate write requests against a fake tool receipt; do not turn a training exercise into a production action.

The harness trace exercise demonstrates runtime behavior with scripted proposals. It does not measure a real model’s resistance to prompt injection or make a claim that a particular product is secure.
