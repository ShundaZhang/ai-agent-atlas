01 / FIELD NOTES

带真实工作区的代码任务

使用 Codex 探索、编辑、执行检查并生成可审查的代码修改。

按代码和反馈位置选择入口：桌面应用组织项目与任务，IDE 保持邻近代码可见，CLI 从仓库运行，云任务使用配置好的远程环境。实际工具、网络和权限取决于入口及设置；不能假设某任务能看到所有文件，或与另一任务使用相同环境。

首次修改前明确仓库、相关路径、工作区状态及快速验证方法。给出具体行为变化及约束，检查最终 diff 和实际检查结果，而不仅看解释。

02 / FIELD NOTES

让仓库上下文简洁且持久

AGENTS.md 承载仓库指引；Skill 承载专门工作流。

Codex 按文档规定的范围和优先级发现适用指令文件。记录稳定事实：环境设置、架构约束、相关检查及生成文件来源。不要把一次性请求写入全局指令。子目录可能需要自身指引，涉及覆盖时查阅当前文档。

# 仓库指引示例
HTML 由 build.py 生成，应修改内容源文件。
内容修改后运行 python3 -B build.py。
完成前检查本地链接及语言对应页。
报告修改页面及尚未核验的行为。

Skill 应简洁易发现、范围明确可测试。“整理发布说明”技能应指定输入与可审查输出，不应暗中获取发布凭据。

对应资料：Codex：AGENTS.md ↗ · 构建 Skills ↗

03 / FIELD NOTES

一次修改，对应一个可见验收条件

先练习有界补丁，再做大型自主重构。

修复本地账单过滤：租户 A 不应看到租户 B 的记录。
阅读实现和已有示例数据。
保持 API 及合法所有者访问。
复现失败、修改过滤逻辑并执行相关检查。
完成时给出 diff、实际结果及剩余限制。

长任务在工作区保存简短计划及检查点；需要时用分支或 worktree 分开独立修改。按任务采用权限策略；沙箱访问权限与发布授权不同。暂停或中断后继续前，应核对实际状态。
