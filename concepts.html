01 / FIELD NOTES

Separate the layers

“AI” can name a field, a model, an application or a whole operating system around a task. Ask which one is being discussed.

TermMeaningExample / boundary
AIMethods for perception, prediction, planning and actionIncludes search, rules and learned models

LLMA large learned language model; often also processes other modalitiesProduces outputs conditioned on its input
AgentA system that chooses actions, observes results and continues toward a goalAn LLM can be its decision component
HarnessThe surrounding runtime that makes the loop operableContext, tools, permissions, state, tracing and stopping

02 / FIELD NOTES

Know what changes when the system learns

A neural model changes its parameters during training. A conversation can change the information supplied to inference without updating those parameters.

Supervised learning uses input/target pairs. Self-supervised learning derives targets from the data itself, such as the next token. Unsupervised objectives discover structure without the same explicit target labels. Reinforcement learning optimizes behavior from reward signals across actions. These labels describe training objectives, not mutually exclusive products.

If you attach a new design document, retrieve a paragraph or save a project note, the next response can improve because the system now has better evidence. That observation alone is not evidence of fine-tuning. Keep parameter learning, in-context adaptation and persistent application memory separate.

03 / FIELD NOTES

Choose the smallest useful system

Autonomy adds a runtime problem as well as a modeling problem.

For a fixed conversion with clear rules, ordinary code may be sufficient. For one document explanation, a model response may suffice. For a question over changing documents, retrieval may help. For a repository fix that requires exploration and tests, an agent loop is useful. For repeated deployment or customer data access, add durable state and authorization to the runtime.

An effective first question is “What evidence marks this task complete?” A code patch, a cited table and a sent message have different completion conditions. A fluent final response is not proof that the underlying action happened.
