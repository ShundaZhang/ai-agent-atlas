工具 / MCP
从概念到实践

工具 schema、MCP、Skill 及资源授权

模型提出调用，应用负责执行工具、MCP 与 Skill 相互补充每个资源边界都应检查授权
01 / FIELD NOTES

模型提出调用，应用负责执行

函数调用连接生成的参数与真实代码。

提供名称明确、输入 schema、输出结构、副作用说明及错误契约清楚的窄功能。模型可选择函数及参数，应用验证、检查权限、执行操作并返回观察。返回“文件已保存”的文本不能证明文件存在。

优先使用含稳定标识及显式错误类型的结构化结果，设置超时及返回大小限制。为策略需要区分查询与更新；写入使用可安全重放的语义，报告真实版本或回执，不用乐观成功句代替。

对应资料：OpenAI：函数调用 ↗

02 / FIELD NOTES

工具、MCP 与 Skill 相互补充

集成协议不自动提升智能或权限。

组件职责不保证什么
工具可调用的输入 / 输出操作参数正确或获准使用
MCP将 host / client 连接到提供工具、资源及提示的 server 的协议每个工具都可信、每位用户都有权限
Skill 技能可发现的重复工作流指令及资源新增 OS 权限或确定性遵守
插件 / 连接器产品封装及服务集成所有产品中能力一致

Skill 可描述怎样组合工具，也可包含辅助脚本。检查来源及触发范围。稳定仓库事实放项目指令，专门的重复过程放 Skill，本次任务放当前提示。避免在三处复制全部规则。

对应资料：MCP：基本概念 ↗ · 构建 Skills ↗ · Codex：AGENTS.md ↗

03 / FIELD NOTES

每个资源边界都应检查授权

MCP 登录成功不等于有权读取所有对象或执行所有动作。

动作执行处检查已认证用户、当前任务、工具范围及资源 ACL。工具描述来自集成，是数据而不是授权。外部文档可能包含建议命令，应在任务范围内检查，而非自动获准执行。

文档搜索应测试 A 用户不能在生成器看到之前检索 B 用户私有段落；写工具应测试重试同一已接受操作不会重复效果；日志应记录决策而不嵌入凭据。

对应资料：MCP：授权 ↗ · OpenAI：沙箱安全 ↗
