01 / FIELD NOTES

模型外围的运行时

Harness 是宽泛工程术语，不同实现的职责范围可能不同。

本站将 Agent Harness 指为组装模型输入、提供工具定义、路由建议、记录观察并推动下一轮的运行时，它还连接终止、超时、状态持久化及应用权限检查。模型权重文件本身不能完成这些工作。工程中的 test harness 则负责驱动测试案例和断言，两种含义都存在。

区分控制与计算。可信应用可管理身份、工具策略及持久审计状态，沙箱处理限定文件与命令。容器是执行环境，不是完整 Harness，默认也不是完整安全边界。

02 / FIELD NOTES

循环很小，契约是关键

下例是与提供方无关的伪代码，不是 OpenAI API 调用配方。

for turn in range(max_turns):
    context = assemble(goal, trusted_rules, observations, checkpoint)
    proposal = model_step(context, allowed_tool_schemas)
    if proposal.is_final:
        return verify_final(proposal, acceptance, observations)
    call = validate_schema(proposal)
    authorize(user, task_capability, call)
    result = execute_with_timeout_and_idempotency(call)
    observations.append(normalize(result))
    persist_checkpoint(observations, workspace_revision)
return stopped("turn_budget", checkpoint)

Schema 验证检查结构；授权检查主体、资源及动作；执行报告成败；验证检查任务属性。要将决策分开：格式正确的请求可能未获授权，获准并成功的工具调用也可能生成错误产物。

03 / FIELD NOTES

从事实恢复，而不是从乐观摘要恢复

持久会话需要记录产物及副作用。

有用的检查点记录任务与约束、最近工具结果、调用 ID、工作区版本、已验证产物、待完成工作及资源消耗。重连后检查实际产物并核对待定动作；不能因为响应丢失就认定中断调用失败。

临时故障可有限重试并退避；确定性 schema 错误不应盲目重试。送回上下文前压缩工具结果，同时保存可检查的原始证据。追踪工具路径及可观察效果，无需收集模型私有推理或无关秘密。

对应资料：OpenAI：Agent 工作流评估 ↗ · OpenAI：Sandbox Agent ↗

选择编排由谁负责

OpenAI 提供多个路线，它们的术语与生命周期不能混用。
