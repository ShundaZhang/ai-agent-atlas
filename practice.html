02 / FIELD NOTES

Three small projects with visible evidence

Each project exercises a different layer without depending on all the others.

Document study in ChatGPT. Supply two public specification revisions. Ask for ten changed requirements with section references, plus two unchanged requirements as controls. Verify every row. Record unsupported and ambiguous claims rather than removing them from the denominator.

Code repair in Codex. Use a disposable repository with a known filter bug. State the invariant, give fixtures and ask for the minimal relevant patch. Review the diff, run owner/non-owner checks and record a case outside the tested scope.

Harness engineering. Run the downloaded scripted harness. Read the event stream, inspect authorization before execution, and change one timeout or step bound. Extend the validator and its tests together. Replace the fake planner with a model only after the runtime contract is understood.

03 / FIELD NOTES

Keep a reusable task and evaluation notebook

A reproducible workflow needs more than a saved prompt.

Download the bilingual task notebook ↓

Record the task, source revisions, acceptance condition, configured capabilities, observed result, failures, cost/latency and retest. Keep the current product documentation link beside product-specific instructions. New model and runtime releases are reasons to rerun representative checks, not reasons to assume every old prompt is obsolete.
